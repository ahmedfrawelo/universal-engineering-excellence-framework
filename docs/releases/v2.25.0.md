# UEEF 2.25.0

Release date: 2026-08-03

## Summary

This release makes Codex enforcement and repository intelligence native UEEF runtime capabilities. It embeds a complete, attributed Graphify engine, exposes governed cross-platform entrypoints, and proves activation through runtime status, drift, and source-revision checks.

## Added

- Added managed Codex enforcement policies, hooks, route recording, and runtime activation checks.
- Added pack 63 for repository intelligence with PowerShell and Unix entrypoints.
- Added a complete Graphify vendor snapshot with upstream file inventory, modification ledger, licenses, notices, and a deterministic vendor verifier.
- Added focused repository-intelligence and managed-enforcement tests on Windows and Unix paths.

## Hardened

- Made embedded engine paths, caches, hooks, installers, exports, watch queues, and test fixtures reliable on Windows while retaining cross-platform behavior.
- Kept optional Obsidian export and external FalkorDB checks opt-in; neither is required for routine UEEF activation.
- Extended the governed runtime file policy so generated vendor segments cannot create false source/runtime drift.
- Required repository-intelligence status, managed enforcement status, runtime drift, and source revision to agree before Codex runtime activation is claimed.

## Verification

- The complete embedded engine suite passed with 3,846 tests and 94 documented platform or optional-dependency skips.
- PowerShell and Unix repository-intelligence tests passed in the source checkout.
- Framework validation passed on Windows and Unix paths.
- Vendor verification proved the complete upstream inventory, tracked UEEF modifications, retained licenses, and absence of nested Git metadata.
- Installed runtime validation, drift, and source revision must pass again for the final release commit after synchronization.

## Compatibility

The release is backward compatible. Repository intelligence is locally invoked and does not run an LLM, database, Obsidian export, browser, or watcher unless the selected command explicitly requests that capability.
