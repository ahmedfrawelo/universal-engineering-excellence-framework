# UEEF 2.19.1

Release date: 2026-07-29

## Summary

This patch adds a dedicated performance forensics workflow for evidence-first investigation of slow tables, grids, dashboards, APIs, SQL queries, cache paths, frontend rendering, and end-to-end bottlenecks.

## Added

- `framework/62-performance-forensics/` with quick triage, full forensic audit, and approved-implementation modes.
- End-to-end flow tracing from navigation through rendering and interactivity.
- Measurement guidance for cold start, warm path, cache hit/miss, pagination depth, filtering, sorting, search, concurrency, and production-like data volume.
- Checklist domains covering pagination, cache, SQL Server, indexes, schema, Entity Framework, backend/API, authentication, payloads, frontend/grid rendering, network, infrastructure, concurrency, architecture options, and observability.
- Version/runtime checks for .NET, Angular, Entity Framework, SQL Server, Redis, data-grid libraries, hosting, OS, proxy, CDN, authentication provider, and deployment model.
- Hidden duplicate-work checks for repeated requests, route guards, resolvers, interceptors, polling, retries, inactive tabs, eager modal/dropdown loads, lookup downloads, and grid recreation.
- Correctness, security, tenant isolation, cost, operational impact, rollback, and approval-gate requirements for every proposed optimization.
- A reusable performance forensics report template.
- `scripts/test-performance-forensics.ps1` and validation coverage.

## Changed

- The master loader now routes slow table, slow grid, slow dashboard, slow API, SQL performance, cache-versus-query, frontend render performance, and explicit performance audit tasks to `framework/62-performance-forensics/`.
- Audit-mode performance work is explicitly report-only until the user approves implementation.
