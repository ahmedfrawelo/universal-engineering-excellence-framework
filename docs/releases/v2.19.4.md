# UEEF 2.19.4

Release date: 2026-07-31

## Summary

This patch hardens Codex runtime activation and makes bootstrap, capability, encoding, and CI evidence fail closed instead of reporting false readiness.

## Changed

- The generic runtime installers now reject `codex`; Codex must use the dedicated installer that generates the runtime loader and managed `AGENTS.md` together.
- Active-state writers and validators require `requireAgents=true` for Codex.
- Windows and Unix status checks validate the runtime agent, the managed `AGENTS.md` version, and current loader integrity.
- Environment bootstrap requires the authoritative runtime status to report `Overall: ACTIVE`.
- Capability health inventories cached and remotely installed plugins plus plugin-owned skills while keeping live session, connection, and callability claims unverified.
- Generated Arabic runtime text is safe under Windows PowerShell 5.1, with an encoding regression test.
- Direct Windows PowerShell 5.1 assurance invocation now resolves the repository root reliably.
- Windows CI runs full assurance, `actions/checkout` is pinned to verified `v7.0.1`, and the Unix source-status test is executable.
- Full-assurance timing limits now cover the expanded runtime tamper fixtures with measured headroom while remaining enforced.

## Verification

- Installer, runtime-hardening, bootstrap, capability, script-syntax, and browser-contract regression suites pass.
- Windows and Unix status fixtures reject stale Codex state and rules.
- Full framework validation and full assurance are required before publication.
