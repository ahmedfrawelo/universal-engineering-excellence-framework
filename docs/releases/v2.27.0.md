# UEEF 2.27.0

Release date: 2026-08-10

## Highlights

- Completes the independent UEEF Spec workflow runtime: deterministic route-bound compilation, persisted fenced execution, live leases, bounded scheduling, restart recovery, verification, and convergence.
- Makes real Codex App Server execution mandatory for managed production while preserving explicit external and test modes without false production claims.
- Adds signed, identity-bound approval gates and package attestations with expiry, revocation, anti-rollback, compatibility, provenance, and policy verification.
- Adds content-addressed multi-layer template composition, atomic package activation and exact rollback, portfolio DAG orchestration, truthful control-plane aggregation, and governed catalog management.
- Keeps the installed Spec Kit `v0.16.1` snapshot as immutable provenance and review evidence only; UEEF production code does not import or execute it.

## Reliability and security

- Host contracts bind workflow, execution, graph, route, execution spec, task, attempt, lease generation, fence, shell policy, and acceptance evidence.
- Direct `READY` execution, expired-lease receipts, stale/deleted-state compare-and-swap, token-budget overrun, malformed persisted states, forged route envelopes, and non-allowlisted shell commands fail closed.
- A durable per-attempt token ledger remains consistent through replan and convergence migrations.
- SQLite serializes each canonical state cycle across readiness, dispatch, receipt validation, and apply; crash tests prove transaction release and same-state retry.
- Installed-reference verification uses a schema-v2 exact manifest, unambiguous length-prefixed digest, canonical portable paths, full coverage, and link, hardlink, reparse, tamper, and TOCTOU defenses.

## Compatibility boundary

- UEEF provides selected equal-or-stronger governed production semantics, not format-wide Spec Kit CLI, plugin, editor, or integration parity.
- Executable hooks, commands, prompts, unrestricted expressions, unbounded expansion, and runtime imports from the reference snapshot remain intentionally unsupported.
- Generic and Claude adapters remain available only through explicit non-production modes unless backed by equivalent verified host evidence.
