# UEEF 2.21.0

Release date: 2026-07-31

## Summary

This minor release turns the expanded frontend skill collection into a reproducible UEEF capability system. Every preferred skill now has installation evidence and declared health, locally owned skills have canonical bundled sources, and Windows and Unix consume the same explainable route contract.

## Added

- Expanded the preferred manifest to 27 pinned or bundled skills.
- Added canonical bundled sources for `company-data-table`, `design-system-guardian`, `frontend-visual-qa`, and `angular-table-harness`.
- Added deterministic Windows and Unix installation support for bundled, GitHub-pinned, and manual-only skills.
- Added route evidence for intent, scope, mutation, domains, stack, confidence, selected modules, skills, and gates.

## Changed

- Made `angular-developer` the implementation authority for Angular routes instead of stacking a framework-general skill with conflicting examples.
- Kept `frontend-ui-engineering` on framework-neutral implementation routes.
- Classified visual QA as a read-only audit, including terse visual-QA requests.
- Synthesized preferred-skill declarations into capability health from the pinned manifest, avoiding duplicated provenance.
- Kept `browser-testing-with-devtools` installed for portability but disabled automatic model invocation under UEEF browser policy.

## Fixed

- Prevented backend, authorization, and security-only work from receiving frontend modules, skills, gates, or reasons.
- Prevented stale staged content from being copied into managed runtimes by making bundled skill sources tracked release assets.
- Allowed bundled skills to install without requiring Python or the GitHub skill installer.

## Verification

- All 27 preferred skills are declared and installed in the active Codex home.
- Frontend routing tests cover 43 assertion groups plus process-level integration and timing checks.
- Capability health, capability profile, task classification, preflight, quality-gate selection, and runtime-hardening tests pass.
- Full Windows framework validation passes with 774 Markdown files and 63 framework packs.
- The managed Codex runtime synchronizes cleanly and reports `ACTIVE` with no runtime drift.

## Compatibility

- Existing task descriptions and explicit frontend-mode overrides remain supported.
- Skill installation and runtime synchronization remain separate, reversible operations.
- Unix scripts retain parity, while this release's full local execution evidence was produced on Windows.
