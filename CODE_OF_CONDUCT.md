# Code of Conduct

UEEF work must be factual, scoped, and evidence-first. Treat people respectfully and evaluate claims by current source, runtime status, tests, and reproducible behavior.

## Expected behavior

- Be direct and professional.
- State evidence and limits clearly.
- Preserve unrelated user work and private data.
- Review architecture, security, performance, accessibility, testing, and maintainability in proportion to the task.
- Prefer small reversible changes over broad unverified rewrites.

## Unacceptable behavior

- Publishing secrets, credentials, private user data, browser profile data, cookies, passwords, history, or storage.
- Claiming completion, release, push, runtime activation, browser verification, or performance improvement without current evidence.
- Hiding known problems, remaining work, failed checks, or weak evidence.
- Using destructive commands or external publishing outside the user's explicit scope.
- Treating build success as proof of behavior when the requested behavior itself was not verified.

## Enforcement

If a contribution violates this code, stop the unsafe action, preserve evidence, report the exact problem, and continue only through the safe in-scope path.
