# quality gate system

Version: 1.0  
Pack: 27-quality-gates  
Status: Stable  
Applies To: tasks where quality gate system materially affects the outcome

## Purpose

This module establishes the enforceable **quality gate system** contract for objective release and completion acceptance gates. It exists to turn that concern into explicit decisions, safeguards, and completion evidence.

## Apply When

- The request names quality gate system or changes behavior governed by it.
- Repository inspection finds an affected boundary, convention, artifact, or risk.
- A reviewer cannot prove the outcome without making the quality gate system decision explicit.

## Required Decisions

1. State the observable outcome and owner for quality gate system.
2. Map each required gate to a risk and executable or inspectable evidence.
3. Record assumptions, rejected alternatives, and the condition that would require revisiting the decision.

## Mandatory Safeguards

- A warning or skipped check cannot silently become a pass.
- Reuse the repository's existing owner, pattern, and automation before adding a parallel mechanism.
- Keep failure behavior explicit, bounded, diagnosable, and recoverable in proportion to risk.

## Required Evidence

- Direct evidence that the quality gate system outcome works in the changed context.
- gate output that records pass, fail, skip reason, and evidence source.
- A focused regression check for the nearest behavior that could be broken.
- For T2+ work, a complete artifact generated by `scripts/new-task-evidence.ps1` and accepted by `scripts/validate-task-evidence.ps1` for every selected gate and domain.
- Command and test evidence includes a zero exit code and observation time; review evidence names its reviewer; file evidence exists and has a matching SHA-256 hash.

## Failure Conditions

- The quality gate system decision is implicit, ownerless, or contradicted by the implementation.
- Evidence demonstrates only intent, compilation, or a happy path when stronger proof is practical.
- Residual risk is hidden, unbounded, or handed off without an owner and trigger.
- A selected gate or domain is omitted, left pending, supported only by a placeholder, or backed by unverifiable provenance.

## Completion Contract

Pass only when the decision, implementation, evidence, and remaining risk agree. Otherwise report the exact failed condition and required next action.
